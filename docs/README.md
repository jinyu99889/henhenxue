## 第一轮需要确认的决策

以下结论已按推荐方案写入文档；在开始编码前请确认或修改。

1. 知识树以不可变版本保存。节点编辑、移动、排序等人工调整均生成新版本，历史版本可回看，避免改写破坏既有学习记录。
2. Markdown 标题构成知识树节点，段落、列表和代码块只归属于最近标题。根节点和非叶子节点仅用于浏览其完整子树；只有叶子节点可以追问，追问只形成对话消息，不自动改动树。
3. 题库是用户私有库，不提供公开或共享。题目可手工录入，或由用户在 [MinerU](https://mineru.net/) 手动转换后上传输出 `.zip` 包；压缩包最大 30 MiB，解析出的题目须经用户审核发布。
4. 主观题第一期采用“会/不会”自评，不把大模型判卷作为默认行为；后续可在现有答题记录上增加异步 AI 评价，不改变核心表。
5. 事务一致性采用本地事务加 Outbox 事件表，再由 RocketMQ 异步投递。RocketMQ 事务消息仅用于确有半消息协调需求的场景，不能替代跨服务业务事务。
6. AI 仅接入 DeepSeek 和阿里云百炼（DashScope）。用户选择提供商后只输入 API Key 与模型名；服务端固定官方地址连接校验，失败即提示且不保存凭据。
7. 答错或标记“不会”的题目自动加入每个用户唯一的错题知识库；它与普通题库一样可被单独选择刷题。
8. 刷题范围支持指定一个或多个个人题库，以及创建会话时的全部个人题库；会话创建后固定题目集合并按题目 ID 去重。
9. 登录使用账号密码，邮箱验证码仅用于注册邮箱校验和找回/重置密码。
10. 管理员由数据库初始化并赋予 RBAC 的 `ADMIN` 角色，不提供前台管理员注册或角色提升入口。
11. 推荐单体仓库、多模块微服务、React 19 独立前端。初期服务边界固定，但允许本地以少量进程启动，降低个人项目的运维成本。
12. AI 生成内容不在树或正文中逐项标注，站点右下角固定展示“AI 辅助生成，请自行核实”。
13. AI 调用只对可重试错误做内部重试，不自动切换用户模型；失败后反馈用户。
14. MinerU 原 ZIP 保留 15 天；MySQL 每日备份与 MinIO 增量备份均保留 7 天。
15. “生成直接子节点”和“从节点生成新树”保留为后续版本能力；首期不在界面和服务流程中开放。
16. 一期永久使用单个 MySQL schema；可靠消息统一写入 `sys_outbox_event`，幂等统一写入 `sys_idempotency_record`，通过服务类型字段区分来源。未来只考虑按业务 ID 水平分表/分库，不做按服务垂直拆分。
17. 文章状态为 `DRAFT`、`SCHEDULED`、`PUBLISHED`、`OFFLINE`、`ARCHIVED`；已发布或定时文章禁止编辑，必须先下架。
18. 软删记录的活跃唯一性使用生成列，不把可空 `deleted_at` 直接放进唯一索引；扩展 JSON 仅按需用于聚合根，不能作为每张表的通用字段。

## 术语约定

- `知识树`：用户围绕一个原始问题建立的学习图谱，展示形态是树。
- `节点键（nodeKey）`：同一知识树中稳定的逻辑节点标识；树版本切换后仍用于定位同一概念。
- `树版本`：一次完整且不可变的树快照。
- `题库`：用户组织题目的容器，可包含手工录入和文档导入的题目。
- `练习会话`：一次特定模式、范围和顺序的刷题过程。
