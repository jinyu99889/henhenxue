# 狠狠学产品需求文档

## 1. 定位与目标

狠狠学是以个人博客为入口、以 AI 知识树学习和私人题库练习为核心能力的个人知识系统。第一期服务于注册用户与站点管理员，不做公开题库交易、多人协作编辑或自动主观题判卷。

核心目标：

1. 读者可以稳定浏览、检索和互动博客内容。
2. 用户能把一个自然语言问题沉淀为可导航、可追问、可扩展的知识树。
3. 用户能从文档或手工输入建立题库，并通过背题或作答完成复习。

## 2. 用户与权限

| 角色 | 权限 |
| --- | --- |
| 访客 | 浏览公开文章、分类、标签与归档 |
| 注册用户 | 使用自己的知识树、题库、练习记录和文章收藏；管理个人资料。 |
| 管理员 | 管理文章、分类、标签、用户与全站配置；不能查看用户模型 Key。 |

所有知识树、题库、导入文件、AI 对话和练习记录默认仅创建者可见。文章是否公开由文章状态控制。

## 3. 博客模块

### 3.1 功能范围

- 首页：置顶文章、最新文章、分类/标签入口。
- 文章：Markdown 编辑、草稿、定时发布、公开、下线、版本回溯，以及正文图片/附件上传。仅管理员可上传，附件类型不限制。
- 浏览：文章详情、目录、代码高亮、相关推荐、分类、标签、按月归档。
- 静态页：首期提供“关于我”，使用与文章相同的 Markdown、版本和资源能力，但不进入文章列表与归档。
- 收藏：登录用户可收藏或取消收藏文章。
- 搜索：公开文章支持按标题、摘要和正文全文检索。
- 运营：文章浏览数、收藏数与文章审计日志。

### 3.2 验收规则

- 草稿、定时发布和下线文章不出现在公开列表、搜索与站点地图中。
- 文章发布后内容快照可回溯，公开 URL 使用不可变 `slug`。
- 收藏关系对用户唯一，重复收藏必须幂等；未登录用户不能收藏。

## 4. AI 知识树学习

### 4.1 首次生成

用户输入一个知识点或问题，例如“解释 JVM 垃圾回收”。系统创建学习树和异步 AI 任务，模型以受约束的 Markdown 返回：一个一级标题、层级标题、段落、列表、代码块和引用。后端解析标题层级，形成树节点；原 Markdown 与解析结果同时保存。标题是节点，段落、列表、代码块和引用只是最近标题的正文，不能被解析为节点。

生成完成后，前端展示树与右侧节点详情。解析失败时保留原文并标记任务失败，不生成半成品树版本。

### 4.2 节点追问

只有叶子节点可以提问。根节点和任何仍有子节点的节点均为浏览节点，不展示历史对话、不接受追问，也不得创建 AI 任务。叶子节点追问时传给模型的上下文必须包含：

1. 原始问题。
2. 当前树版本标识。
3. 选中节点及其从根到该节点的祖先路径。
4. 该叶子节点从根到自身的标题路径、直属正文 Markdown、该节点既有消息与用户新问题。

上下文按长度预算截断，优先保留原始问题、节点路径、叶子节点正文和最近消息；不将整棵大树无界地拼入 Prompt。普通追问产生会话消息，不改动知识树。服务端以请求的 `versionId` 判定叶子状态，不能仅根据当前版本或前端传参放行。

### 4.3 节点内容展示

- 点击根节点：展示整棵树的完整 Markdown。
- 点击非叶子节点：展示该节点直属正文及其全部后代节点内容，按原始标题和 `sortOrder` 的深度优先顺序组织。
- 点击叶子节点：只展示该节点直属正文，并展示该节点、该版本下的历史追问与输入区。

父节点不得持久化重复的子树正文。服务端从节点的直属正文和有序后代在读取时聚合展示内容；前端不解析 Markdown 标题或自行拼接子树。

### 4.4 后续：扩展与分支

以下能力保留在数据模型和长期设计中，首期不提供界面入口，也不启用对应 AI 任务：

| 操作 | 输入给模型 | 输出 |
| --- | --- | --- |
| 生成直接子节点 | 原始问题、祖先路径、节点正文、扩展指令 | 在此节点下新增 2-6 个直接子节点的新树版本 |
| 从此节点生成新树 | 原始问题、祖先路径、节点正文、新主题 | 以该节点为根的新知识树 |

树版本不可变。扩展时克隆当前版本、保留已有 `nodeKey`、给新增节点分配新的 `nodeKey`，然后把新版本设为当前版本。用户可在版本间切换和回退，不会丢失旧对话。

### 4.5 模型输出约束

- 标题级别只能从 `#` 开始，不能跳级超过一级。
- 首个标题必须是唯一根节点；节点标题不可为空，单个节点标题在同层内唯一。
- 标题下直属正文归属最近的标题，遇到任意下一个标题即结束；子标题及其正文不写入父节点 `content_md`。不把列表项、加粗文本或编号当作树节点。
- 模型响应还须带结构化元数据：语言、摘要、置信提示和引用列表。正文仍以 Markdown 为唯一展示来源。

## 5. 题库与刷题

### 5.1 建库与导入

用户创建题库后可手工添加题目，或在 [MinerU](https://mineru.net/) 将原始文档转换后上传输出 `.zip` 包。本站不上传、OCR 或直接处理用户原始 Word/PDF/图片文档；只接受一个 MinerU 输出压缩包，压缩包大小不超过 30 MiB。包内必须恰有一个 `.md` 文件，图片资源与 Markdown 一并上传。系统异步解析 Markdown 为候选题目，候选题目状态为 `PENDING_REVIEW`，用户在编辑页确认、修正或删除后发布。

MinerU 为第三方站点，用户自行决定是否向其上传原始文档，并应遵循该站点的隐私政策与使用条款。导入器保存原 ZIP、Markdown 与图片到 MinIO，图片元数据与其在压缩包内的相对路径写入 MySQL；题目中的本地图片路径被重写为站内受权限保护的资源引用。公式按 LaTex、表格按 HTML/Markdown 保留并渲染。任一 Markdown 图片引用无法解析为包内有效图片时，整个导入任务失败，不创建候选题目。

题型：单选、多选、判断、填空、简答/论述。每题存题干 Markdown、选项、标准答案、解析、难度、知识点标签和来源位置。

### 5.2 两种练习模式

| 模式 | 行为 |
| --- | --- |
| 背题模式 `MEMORIZE` | 同屏展示题目、答案与解析；用户标记“已掌握/待复习”。 |
| 作答模式 `EXAM` | 初始仅展示题目。客观题提交后立即显示对错、答案与解析；主观题只显示“会/不会”，不要求输入答案。 |

客观题由服务端判题。单选/多选/判断比较规范化答案；填空支持多个可接受答案和大小写、全半角规范化。第一期不做模糊判分。练习会话保存题目快照，后续修改题库不影响历史统计。同一题目可重复导入或手工创建，不做内容去重。

### 5.3 验收规则

- 一个练习会话可选择一个或多个题库，也可选择创建时的全部个人题库；创建后题目集合和顺序固定。
- 未发布、已删除或不属于用户的题目不能进入会话。
- 客观题答案不能在作答提交前通过列表或接口泄露。
- 一个题目可同时属于普通题库和错题知识库；按“全部个人题库”创建会话时，按题目 ID 去重。
- 答错的客观题、主观题的“不会”以及背题模式的“待复习”自动加入用户唯一的错题知识库；答题结果页提供“移出错题库”动作，由用户主动移除。

## 6. 非功能要求

- AI 生成与 Markdown 题目解析均异步化，页面以 SSE 展示进度和流式内容。
- 用户数据按 `user_id` 强制隔离；对象存储 URL 使用短时预签名地址。
- 可观测性覆盖请求 ID、AI 任务 ID、导入任务 ID、消息投递和定时任务。
- 所有修改性请求具备幂等键；关键操作写审计日志。
- 用户不提供自助注销账号入口；管理员仅可禁用账号，禁用后保留其数据和审计记录。
- 所有页面右下角固定显示“AI 辅助生成，请自行核实”；知识树、题目、文章正文不重复插入该标注。

## 7. 已确认边界

1. 博客仅允许管理员发布；注册用户不拥有文章空间。
2. 用户名或邮箱均可配合密码登录。邮箱验证码用于注册校验、找回/重置密码；已登录修改密码只校验旧密码，不提供纯验证码登录。
3. AI 模型 Key 由用户自行提供；第一期固定接入 DeepSeek 和阿里云百炼（DashScope），不开放自定义 Base URL。用户输入 Key 和模型名后必须先完成连通性校验。知识树保存默认模型；题库 ZIP 每次导入显式选择模型。
4. 知识树允许编辑、排序和移动节点，任何修改均生成新版本。
5. 题库固定为个人私有，不提供共享或公开；上传仅支持 MinerU 输出的 ZIP 包，最大 30 MiB，保留其 Markdown、公式、表格和图片资源。
6. 错题本为用户自动创建的唯一错题知识库；首期保留掌握记录，不实现间隔重复算法。题目允许重复，不以内容哈希去重。
