# 狠狠学前端实施指南

## 1. 推荐路线

采用独立的 React 19 + JavaScript + Vite 工程。首期原型使用 `motion` 提供界面动效、`lucide-react` 提供图标，样式使用 plain CSS；后续业务页面按需要接入路由、状态和 HTTP 层。知识树采用可交互图组件实现，节点详情与提问面板保持在同一工作区。

前端不承担鉴权、判题、Markdown 树解析或文件权限判断。它负责收集输入、展示服务端状态、维持会话和处理 SSE；任何按钮隐藏都不能替代后端授权。

## 2. 页面信息架构

| 路由 | 页面 | 关键区域 |
| --- | --- | --- |
| `/` | 博客首页 | 文章流、分类、标签、搜索。 |
| `/article/:slug` | 文章详情 | Markdown 正文、目录、收藏。 |
| `/about` | 关于我 | 静态 Markdown 页面。 |
| `/learn` | 我的知识树 | 树列表、搜索、新建入口。 |
| `/learn/:treeId` | 知识树工作台 | 左树图、中节点正文、右追问/版本面板。 |
| `/question-libraries` | 我的题库 | 题库列表、新建、导入入口。 |
| `/question-libraries/:id` | 题库编辑 | 导入进度、题目审核、手工题目表单。 |
| `/practice/setup` | 开始刷题 | 题库多选、模式、题型、数量、顺序。 |
| `/practice/:sessionId` | 刷题工作台 | 进度、题目、答题区、结果/解析。 |
| `/admin/*` | 博客管理 | 文章、分类标签、用户与配置。 |

文章编辑器通过上传接口插入正文图片/附件，Markdown 保存 `asset://{fileId}` 引用；保存草稿前由服务端校验资源归属，历史版本预览使用该版本绑定的资源。

应用根布局右下角固定展示“AI 辅助生成，请自行核实”，不随路由滚动或遮挡移动端底部操作区；该标注不注入文章、题目或知识树 Markdown。

## 3. 知识树工作台

桌面端采用三栏：左侧 280px 树导航，中部为可缩放树图，右侧 360px 节点详情与追问区。窄屏切换为“树图 / 节点详情 / 提问”标签页，避免在手机上并排挤压。

- 节点点击后高亮从根到选中节点的路径，右栏展示标题、正文、祖先面包屑。根节点展示整棵树，非叶子节点展示其子树，叶子节点展示直属正文；展示 Markdown 由服务端节点内容接口返回，前端不解析或拼接标题树。
- 只有叶子节点显示追问历史和输入区。“追问”提交后创建会话并订阅任务 SSE；流式内容在消息气泡中增量渲染，完成前不允许重复提交。根和非叶子节点仅展示浏览状态。
- 树导航按父子节点支持展开、折叠；折叠状态是纯前端交互状态，不改变树版本。
- “生成直接子节点”和“从此节点生成新树”属于后续功能，首期不渲染入口，也不调用扩展接口。
- 版本下拉框可回看历史；当前版本与生成中的版本必须视觉区分。
- 渲染服务端返回的 Markdown 前必须做 HTML 白名单净化，外链默认 `noopener noreferrer`。

## 4. 题库与练习交互

- 题库导入页提供 [MinerU](https://mineru.net/) 外链，在新窗口打开；站内只接受用户转换后上传的 MinerU `.zip` 输出包，限制 30 MiB。上传后显示 Markdown、公式、表格、图片资源的解析和人工审核状态，不提供 OCR 进度或原始 Word/PDF/图片上传入口。
- 候选题目在审核列表中可逐题编辑、批量发布、批量归档。多选题必须限制至少两个选项和至少一个正确答案。
- 背题模式固定展示答案/解析，并提供掌握状态按钮。
- 作答模式提交前绝不渲染答案字段；客观题用单选框、多选框、判断按钮或填空输入框；提交后锁定并展示反馈。
- 当题目已进入错题知识库时，作答结果区展示“移出错题库”，点击后只移除错题库关联。
- 主观题只有“会”和“不会”两个明确按钮，结果直接记录为自评。
- 刷题范围在开始页提供“选择题库”和“全部我的题库”两个模式；选择全部时，页面要提示范围会在开始时冻结。
- 错题知识库在题库列表中使用系统标识并禁止改名；当用户答错或点“不会”后显示“已加入错题知识库”。选择全部题库时前端不自行去重，由服务端按题目 ID 固化去重后的会话快照。

## 5. 面向后端协作的契约

- 所有页面必须处理 `PENDING`、`RUNNING`、`READY`、`FAILED`、`CANCELLED` 状态，不根据字符串猜测任务完成。
- SSE 连接断开后使用 `Last-Event-ID` 或任务状态接口恢复；收到 `completed` 后重新拉取树版本或导入结果。
- 列表使用服务端分页、排序、筛选，不在浏览器下载全量数据再过滤。
- 前端只使用服务端返回的资源 ID；不自行构造 MinIO 地址，不在 localStorage 保存业务权限。
- 模型配置表单只提供 DeepSeek/阿里云百炼两个提供商选择、模型名和 API Key，不出现 Base URL 输入框。提交期间显示连接中；成功后列表只展示提供商、模型、脱敏指纹和验证状态，失败则展示后端返回的可理解错误。前端不缓存或再次展示明文 Key。
- 错误统一读取 `code`、`message`、`traceId`，显示可理解提示并给出重试；把 `traceId` 留给用户复制反馈。

## 6. 前端开发顺序

1. 登录态、布局、路由守卫、错误与任务状态组件。
2. 公开博客阅读与后台文章编辑。
3. 文件上传、题库审核和两种刷题模式。
4. 知识树生成、SSE、节点详情、叶子节点追问与版本切换。
5. 统计和后台运营页；树扩展在后续版本另行排期。
